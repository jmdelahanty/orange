# Orange Calibration Artifact Contract

Purpose: define the producer-side contract for immutable calibration artifacts
generated by Orange.

Date anchored: 2026-03-16.

Scope:
- Orange-generated calibration artifact packages.
- Package layout, manifest shape, and reference shape for downstream consumers.

Non-scope:
- Consumer-specific UI behavior.
- Legacy Citrus filename-convention calibration loading.

Interpretation guide:
- See `docs/aperture_calibration_usage.md` for how to use aperture artifacts,
  how reference f-number anchoring works, and what transfers across exposures.
- See `docs/target_derived_calibration_plan.md` for the USAF resolution artifact
  design, the current manual-annotation v1 workflow, and the planned DOF follow-up.
- See `docs/calibration_image_set_schema.md` for the generic acquisition
  artifact Orange should use for Citrus-imported homography, scale, top-rim,
  and crosshair calibration image sets.

## Ownership

Orange owns:
- generation of camera/lens calibration payloads
- artifact bytes on disk
- manifest metadata for those payloads

Downstream consumers should bind these artifacts to rig/canvas/arena context by
reference rather than treating file paths as identity.

## Artifact Root

Session-scoped Spatial Layout artifacts are now the canonical path for daily
camera/arena calibration work:

```text
~/orange_data/calibrations/sessions/<session_id>/artifacts
```

Older standalone calibration tools, such as aperture characterization and USAF
resolution measurements, use a separate non-session default:

```text
~/orange_data/calibrations/standalone_artifacts
```

The legacy top-level `~/orange_data/calibrations/artifacts` directory is retired
as a default write target. New Spatial Layout saves should refuse to write
there; they must create or reuse a calibration session.

Each artifact package still lives in its own directory beneath the active
session or standalone root. Spatial Layout may add typed grouping directories
inside the session root, for example `Cam<serial>_<arena_id>/` aggregates and
`top_rim_observations/<artifact_id>/` children:

```text
<artifact_root>/<artifact_id>/
<artifact_root>/Cam<serial>_<arena_id>/
<artifact_root>/Cam<serial>_<arena_id>/top_rim_observations/<artifact_id>/
```

`artifact_id` is a stable handle for the package. It is the package directory
name and should be treated as the artifact identity.

Artifact registry:

```text
<artifact_root>/index.json
```

Orange updates this registry on every successful artifact write. Consumers may
resolve via `artifact_id -> relative_manifest_path` using this file instead of
guessing paths.

## Package Layout

Current aperture characterization package layout:

```text
<artifact_id>/
├── manifest.json
├── measurement.json
├── steps.csv
├── frames.csv
├── camera_config_snapshot.json
├── fov_reference_frames/
└── representative_frames/
```

Notes:
- `representative_frames/` may be absent or empty when frame saving is disabled.
- `fov_reference_frames/` may be absent or empty when no horizontal/vertical
  ruler captures were attached to the run.
- `camera_config_snapshot.json` may be absent when Orange could not resolve the
  source camera config path for the run.
- `measurement.json`, `steps.csv`, and `frames.csv` are the payload files for
  the aperture artifact.

Current USAF 1951 resolution package layout:

```text
<artifact_id>/
├── manifest.json
├── measurement.json
├── positions.csv
├── camera_config_snapshot.json
├── target_reference_frames/
└── analysis_overlays/
```

Notes:
- `target_reference_frames/` contains the raw captured position images.
- `analysis_overlays/` contains ROI-overlay audit images written from the same captures.
- USAF v1 uses manual resolved-element annotation per captured field position; it does
  not yet auto-read the target.

Implemented generic calibration image-set package layout:

```text
<artifact_id>/
├── manifest.json
├── image_set.json
├── captures/
├── overlays/
└── exports/
```

Notes:
- `image_set.json` uses `schema_id = "orange.calibration.image_set"`.
- The image-set artifact is the Orange-owned acquisition package for
  Citrus-imported projection-surface homography/validation captures,
  camera-only physical-target C-plane captures, scale images, dish top-rim
  captures, and crosshair-alignment captures.
- Current dry physical-target height-parallax diagnostics use
  `purpose = "dry_physical_target_height_parallax_diagnostic"`,
  `reference_only = true`, `physical_target_used = true`, and
  `projected_pattern_used_as_coordinate_target = false`. Future accepted
  camera-only physical-target calibration captures use
  `purpose = "camera_only_physical_target_calibration"` with `plane_id` and
  `parity_group_id`. Projected-pattern captures at a moved diffuser, dish/base
  height, or fish height are diagnostics and must not be auto-imported as
  physical `C_base` or `C_fish` maps.
- Spatial Layout normally uses a camera/arena aggregate artifact ID such as
  `Cam2010093_arena_1`, then appends multiple purpose-specific captures under
  `captures/`.
- `exports/` may contain Citrus-compatible staging copies or manifests, but
  those exports are not the durable Orange artifact identity.

## Manifest Contract

Path:

```text
<artifact_dir>/manifest.json
```

Current emitted shape:

```json
{
  "schema_id": "orange.calibration.manifest",
  "schema_version": 1,
  "artifact_id": "aperturecal_...",
  "artifact_schema_id": "orange.calibration.aperture",
  "artifact_schema_version": 1,
  "created_utc": "2026-03-16T22:06:50Z",
  "producer": {
    "application": "orange",
    "artifact_type": "aperture_characterization"
  },
  "calibration_ref": {
    "artifact_id": "aperturecal_...",
    "artifact_schema_id": "orange.calibration.aperture",
    "artifact_schema_version": 1,
    "fingerprint": "fnv1a64:8a6b1c2d3e4f5061"
  },
  "compatibility": {
    "camera_serial": "2010096",
    "lens_name": "EF100mm f/2.8L Macro IS USM",
    "focus": 3100,
    "exposure": 100,
    "gain": 0,
    "pixel_format": "Mono8",
    "width": 4512,
    "height": 4512
  },
  "files": {
    "manifest": "manifest.json",
    "measurement_json": "measurement.json",
    "steps_csv": "steps.csv",
    "frames_csv": "frames.csv",
    "fov_reference_frames_dir": "fov_reference_frames",
    "representative_frames_dir": "representative_frames"
  }
}
```

Notes:
- `fingerprint` is a stable Orange-emitted package fingerprint string.
- Current algorithm: `fnv1a64`.
- The current fingerprint covers the measurement payload plus any
  representative-frame bytes and FOV ruler-capture bytes. It intentionally excludes `artifact_id`,
  `created_utc`, and absolute filesystem roots so the value is content-based
  rather than path-based.
- Consumers should validate `schema_id`, `schema_version`, `artifact_id`,
  `artifact_schema_id`, and `artifact_schema_version` before trusting the
  payload.

## Registry Contract

Path:

```text
<artifact_root>/index.json
```

Current emitted top-level shape:

```json
{
  "schema_id": "orange.calibration.registry",
  "schema_version": 1,
  "artifact_root": "/home/jeremy/orange_data/calibrations/sessions/calsess_.../artifacts",
  "updated_utc": "2026-03-16T22:40:00Z",
  "artifact_count": 1,
  "latest_by_schema": {
    "orange.calibration.aperture": "aperturecal_..."
  },
  "artifacts_by_id": {
    "aperturecal_...": {
      "artifact_id": "aperturecal_...",
      "artifact_schema_id": "orange.calibration.aperture",
      "artifact_schema_version": 1,
      "created_utc": "2026-03-16T22:06:50Z",
      "fingerprint": "fnv1a64:8a6b1c2d3e4f5061",
      "relative_manifest_path": "aperturecal_.../manifest.json"
    }
  }
}
```

Notes:
- `artifacts_by_id` is the authoritative lookup table.
- `latest_by_schema` is a convenience pointer for the newest artifact written by
  Orange for a given schema.
- Consumers should still validate the referenced manifest before trusting the
  payload.

## Payload Contract

Path:

```text
<artifact_dir>/measurement.json
```

Current emitted top-level fields include:
- `schema_id = "orange.calibration.aperture"`
- `schema_version = 1`
- `artifact_id`
- `created_utc`
- `calibration_ref`
- `camera`
- `request`
- `summary`
- `steps`

The detailed aperture measurement payload remains defined by the current writer
in `src/aperture_characterization.cpp`.

Current aperture request fields also include:
- `camera_config_snapshot`
- `fov_calibration`
- `grid_rows`
- `grid_cols`

Current USAF measurement payloads include top-level fields such as:
- `schema_id = "orange.calibration.usaf1951_resolution"`
- `artifact_id`
- `compatibility`
- `request.target_name`
- `request.target_polarity`
- `request.illumination_mode`
- `request.camera_config_snapshot`
- `request.fov_calibration`
- `positions[]` with per-position ROI and horizontal/vertical resolved element data
- `summary.center_single_bar_width_um`
- `summary.best_field_single_bar_width_um`
- `summary.worst_field_single_bar_width_um`

Current per-step payloads may include:
- `has_estimated_effective_f_number`
- `estimated_effective_f_number`
- `has_grid`
- `grid.rows`
- `grid.cols`
- `grid.tile_mean`
- `grid.tile_relative_mean`
- `grid.min_relative_mean`
- `grid.max_relative_mean`
- `grid.cv_relative_mean`

Current `request.fov_calibration` fields may include:
- `enabled`
- `working_distance_mm`
- `pixel_pitch_um`
- `field_width_mm`
- `field_height_mm`
- `sensor_width_mm`
- `sensor_height_mm`
- `magnification_x`
- `magnification_y`
- `mean_magnification`
- `effective_reference_f_number`
- `horizontal_capture`
- `vertical_capture`

Current emitted schema IDs:
- `orange.calibration.aperture`
- `orange.calibration.usaf1951_resolution`

Planned future schema IDs:
- `orange.calibration.image_set`
- `orange.calibration.dof_resolution`
- `orange.calibration.imaging_capability_summary`

## CalibrationRef Contract

Downstream consumers should store references with this minimum shape:

```json
{
  "artifact_id": "aperturecal_...",
  "artifact_schema_id": "orange.calibration.aperture",
  "artifact_schema_version": 1,
  "fingerprint": "fnv1a64:8a6b1c2d3e4f5061"
}
```

Rules:
- `artifact_id` is the identity.
- `artifact_schema_id` and `artifact_schema_version` tell the consumer what it
  should expect from the payload.
- `fingerprint` is a content fingerprint emitted by Orange and should be treated
  as an integrity/provenance check, not as primary identity.
- Absolute manifest paths may be recorded as resolved runtime metadata, but they
  are not identity.

## Consumer Resolution

Consumers should resolve the registry for the specific session or standalone
root they are reading:

```text
~/orange_data/calibrations/sessions/<session_id>/artifacts/index.json
```

Then use `artifacts_by_id[artifact_id].relative_manifest_path`.

Recommended env override:
- `ORANGE_DATA_ROOT`
